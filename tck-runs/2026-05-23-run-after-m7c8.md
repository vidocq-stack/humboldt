- `HumboldtServerRequestFilter` pose désormais 7 attributs OTel SemConv 1.27+ :
  - `http.request.method`, `http.route` (fallback URL_PATH si ResourceInfo null)
  - `url.path` (path **complet** incluant context root, reconstruit via
    `baseUri + uriInfo.getPath()` — Cassini in-process renvoyait un requestUri stripped)
  - `url.query` (raw)
  - `url.scheme`
  - `server.address`, `server.port` (omis si port standard du scheme)
- Span name = `"METHOD route"` (e.g., `"GET /context/span/{id}"` quand route templaté
  disponible, sinon `"GET /context/span/1"` fallback non-templaté)
- `buildRoute` via introspection des annotations `@Path` (classe + méthode) puisque
  `UriInfo.getMatchedTemplates()` n'existe pas dans la spec JAX-RS standard

## Bloqueur identifié → M7c.9

`HumboldtDeployableContainer.deploy()` instancie le filter via `new` et le passe à
`CassiniHarness.Builder.provider(Object)`. Cette API n'invoque pas l'injection JAX-RS
`@Context` → `ResourceInfo` reste null dans le filter.

Solutions possibles :
- Étendre `CassiniHarness.Builder` avec `providerClass(Class<?>)` qui instancie via
  Cassini et fait l'injection JAX-RS (`@Context UriInfo`, `@Context ResourceInfo`, etc.)
- Ou faire un mécanisme de "post-routing property injection" : Cassini pose le
  `ResourceMethod` matché dans une property du `ContainerRequestContext` avant
  d'appeler les filters post-matching, et le filter le récupère via `getProperty()`

Impact estimé : tests qui assertent `HTTP_ROUTE` templaté (RestSpanTest.spanName,
RestSpanDefaultTest, RestSpanDisabledTest, possible JaxRsClient*Test) — ~5-8 tests.
