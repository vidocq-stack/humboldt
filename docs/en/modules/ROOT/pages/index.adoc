= Humboldt
:description: MicroProfile Telemetry 2.1 implementation — distributed tracing, metrics, logs — OpenTelemetry-native, JPMS-strict, zero third-party SDK, Java 25.

[.text-center]
image::humboldt-logo.png[Humboldt,300,role=module-logo]


[.lead]
Humboldt is the MicroProfile Telemetry 2.1 implementation of the Vidocq ecosystem. It implements its own OpenTelemetry SDK (traces, metrics, logs) directly on the OTel API surface, and integrates with xref:chappe::index.adoc[Chappe] for HTTP transport, xref:vauban::index.adoc[Vauban] for CDI, and xref:cassini::index.adoc[Cassini] for JAX-RS instrumentation. Goal: 100 % TCK conformance, no `opentelemetry-sdk` / `opentelemetry-exporter-*` dependency, no Netty, no gRPC stack.

== Origin of the name

**Alexander von Humboldt** (1769–1859), Prussian polymath, naturalist, geographer, explorer. The man who made the founding gesture of modern observability: *observe simultaneously, measure rigorously, correlate across layers*. On Chimborazo in 1802 he recorded jointly barometric pressure, temperature, terrestrial magnetism, humidity, fauna, flora — then drew the first isothermal maps revealing the hidden invariants of the planet. He invented the *Naturgemälde*, the first scientific data visualization.

Reference: https://en.wikipedia.org/wiki/Alexander_von_Humboldt[Humboldt on Wikipedia].

[cols="1,3"]
|===
| Humboldt, the explorer | Humboldt, the runtime
| Simultaneous pressure + temperature + magnetism measurement | Tracing + Metrics + Logs unified through the OTel SDK
| Time-stamped, calibrated field notebooks | Span attributes + monotonic timestamp (`Clock`)
| Isotherms — invariant curves across continents | Span links + W3C TraceContext + Baggage
| Naturgemälde — cross-altitude visualization | Cross-signal correlation `trace_id` → metric → log
| Mobile, embedded instruments (the only ones for the era) | Embedded SDK in-process, no daemon, no agent
|===

OpenTelemetry is the Naturgemälde of distributed systems. Humboldt embeds it natively in Java SE.

Humboldt shares its transport with the rest of the Vidocq ecosystem (Chappe HTTP/1.1 + H2). It does not embed Netty, gRPC-java, OkHttp or any third-party HTTP stack. The future gRPC OTLP exporter will be delivered via a native `chappe-grpc` module (cf. PLAN.md §3.5).
