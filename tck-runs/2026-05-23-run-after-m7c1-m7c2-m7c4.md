## Failure categorization of the 60 failures

### Cluster A — missing REST Client (~18 tests) → **M7c.5 Cyrano MP Rest Client**

```
RestClientSpanTest.setUp:114 Failed to create rest client
RestClientSpanDefaultTest.setUp:95 Failed to create rest client
RestClientSpanDisabledTest.setUp:97 Failed to create rest client
W3BaggagePropagationTest.setUp:91 Failed to create rest client
W3PropagationTest.setUp:91 Failed to create rest client
JaxRsServerAsyncTest.* → IllegalState: No RestClientBuilderResolver implementation found!
```

Cause: no MicroProfile Rest Client 4.0 implementation in the Arquillian
deployment classpath. Solution: add `cyrano` (and its runtime deps) to the
classpath through `HumboldtDeployableContainer`.

### Cluster B — missing or extra spans (~15 tests) → **M7c.6/7 filter logic**

```
RestSpanDefaultTest.span → expected [0] but found [1]
RestSpanDefaultTest.spanName → expected [0] but found [1]
RestSpanDisabledTest.span → expected [0] but found [1]
JaxRsClientAsyncTest.testIntegrationWithJaxRsClient → expected [3] but found [1]
JaxRsClientAsyncTest.testIntegrationWithJaxRsClientAsync → expected [3] but found [1]
```

Two sub-causes:
- `RestSpanDefault/DisabledTest expected 0 found 1`: we emit spans even
  when `otel.sdk.disabled=true` or for internal requests. Check the
  `humboldt-rest` HTTP filter.
- `JaxRsClientAsync expected 3 found 1`: we have 1 SERVER span but not the 2
  expected CLIENT spans. Missing **M7c.7 ClientFilter** (JAX-RS Client filter
  that creates a SPAN_KIND_CLIENT span around each outgoing call).

### Cluster C — incorrect http.route (~1 test) → **M7c.8 UriInfo.getMatchedTemplates()**

```
RestSpanTest.spanNameWithoutQueryString
  expected [/<uuid>/span/1?id=1] but found [/span/1]
```

The `humboldt-rest` filter returns the path **after stripping the context root**,
whereas the spec expects the **full path including the context** + path
parameters. Solution: use `UriInfo.getMatchedTemplates()` and concatenate
with `UriInfo.getBaseUri()`.

### Cluster D — Autoconfigure SPI (~3 tests) → decision (deferred?)

```
CustomizerSpiTest.testCustomizer → expected [test-value] but found [null]
ResourceSpiTest.testResource → expected [test1] but found [null]
SamplerSpiTest.testSampler → expected [false] but found [true]
```

The TCK calls OTel SDK autoconfigure SPIs (`AutoConfigurationCustomizerProvider`,
`ResourceProvider`, `ConfigurableSamplerProvider`). Humboldt does not use OTel
SDK autoconfigure at runtime; the `humboldt-tck` bridge reinjects the SDK
fixture but does not pipe these SPIs into the Humboldt runtime.

Decision: to be arbitrated. Either extend the bridge to propagate customizers
toward `HumboldtAutoConfigure`, or document the exclusion (Humboldt has no
native `AutoConfigurationCustomizer` pipeline, which is compliant).

### Cluster E — missing SDK metric / log (~23 tests) → **M4b** + **M5b**

All `Metrics*Test` tests (DoubleCounter, LongCounter, Histogram, Observable,
JVM metrics) and `Logs*Test` (JulHandler bridge) — tests cited by the M7c
roadmap as dependent on the complete SDK metric / log implementation.
