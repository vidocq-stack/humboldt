## Item delivered in M7c.11

MP Telemetry 2.1 spec §3.1:
> By default, the OpenTelemetry SDK is disabled. To enable it, set `otel.sdk.disabled=false`.

Native OTel SDK Java has the opposite default (`disabled=false`), but for MP Telemetry
conformity, humboldt follows the MP default.

**Patch `HumboldtAutoConfigure.configure(env, extras)`**:
- Reads `OTEL_SDK_DISABLED` with default `true`
- If disabled: builds `SdkTracerProvider`/`SdkMeterProvider`/`SdkLoggerProvider`
  **without any processor** → the OTel API remains usable (`Span.current()`,
  `Tracer.spanBuilder()`) but no signal is ever exported
- Returns `AutoConfiguredHumboldt` with InMemory exporters = null
- Otherwise: current behavior (`otel.sdk.disabled=false` → full pipeline)

**Update to `HumboldtAutoConfigureTest`**:
- All existing tests explicitly set `OTEL_SDK_DISABLED=false` (otherwise the
  default change breaks their assertions on the InMemory exporters)
- 2 new tests:
  - `sdk_disabled_by_default_per_mp_telemetry_spec`: with no explicit config,
    inMemorySpanExporter() == null + 0 SpanProcessor
  - `sdk_disabled_true_explicit_disables_all_pipelines`: explicit
    OTEL_SDK_DISABLED=true + all in-memory exporters → all null
