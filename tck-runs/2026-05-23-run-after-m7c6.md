## Item livré en M7c.6

Nouveau module `cassini-client` (`io.vidocq.cassini:cassini-client:0.1.0-SNAPSHOT`) —
impl `jakarta.ws.rs.client.ClientBuilder` zéro-dépendance basée sur `java.net.http.HttpClient`
+ virtual threads. Découverte via ServiceLoader (`META-INF/services`) et JPMS `provides`.

Périmètre commit #2 :
- `ClientBuilder`, `Client`, `WebTarget`, `Invocation.Builder`, `Invocation`
- Toutes méthodes HTTP synchrones (GET/POST/PUT/DELETE/HEAD/OPTIONS/TRACE/method)
- Templating URI via `CassiniUriBuilder` (réutilisé de cassini-core)
- Headers, accept, queryParam, resolveTemplate
- Réponse via `CassiniClientResponse` (decode UTF-8 + charset Content-Type)
- `CassiniClientRuntimeDelegate` (sous-classe locale de `CassiniRuntimeDelegate` —
  contrainte JPMS qui interdit `provides X with Y` si Y est dans un autre module)

Hors scope M7c.6 (renvoyés à M2d.2 dans cassini ROADMAP) :
- Async via `InvocationCallback` / `CompletionStageRxInvoker`
- Sérialisation request body via `MessageBodyRegistry` (POJO JSON-B…) — commit #3 si nécessaire
- Filtres CLIENT (`ClientRequestFilter`/`ClientResponseFilter`) — commit #4 / requis pour M7c.7

Modifications associées dans cassini :
- `pom.xml` reactor : `<subproject>cassini-client</subproject>` + DM entry
- `cassini-core/module-info.java` : `exports internal{,.runtime} to io.vidocq.cassini.client`
- `cassini/ROADMAP.md` : correction M2d (jalon marqué `✅` par erreur — n'avait jamais été implémenté)

Tests unitaires : **6/6 PASS** (ClientBuilderDiscoveryTest + BasicGetTest avec FakeHttpServer
`com.sun.net.httpserver.HttpServer` éphémère in-process).

## Pourquoi le PASS net est inchangé

Les tests qui utilisaient `ClientBuilder.newClient()` (`BaggageTest`, `RestClientSpan*Test`,
`RestSpan*Test`) crashaient AVANT en setUp avec `ClassNotFoundException`. Avec cassini-client :
- ✅ setUp atteint le runtime (ClassNotFoundException disparait)
- ❌ Tests fail désormais sur des bloqueurs orthogonaux :
  - Spans CLIENT pas instrumentés autour des requêtes JAX-RS Client → **M7c.7** (`humboldt-rest`
    `ClientRequestFilter` + `ClientResponseFilter` qui posent un span `kind=CLIENT` avec attrs
    OTel HTTP semantic conventions)
  - `testIntegrationWithJaxRsClient`, `testIntegrationWithJaxRsClientAsync`,
    `testIntegrationWithJaxRsClientError` : ont besoin de M7c.7
  - `testIntegrationWithMpRestClient*` : ont besoin de M7c.12 (filtres MP Rest Client cyrano)
  - `baggage()` : HTTP 500 côté serveur — investigation nécessaire (SpanResource fait probablement
    un appel sortant ou un accès baggage qui crash)
  - `b3*Propagation`, `jaegerPropagation` : propagators non-W3C optionnels — cluster D

## Validation non-régression cassini

`cassini-client` n'a touché à aucun module existant sauf `cassini-core/module-info.java`
(extension des `exports to` pour autoriser le nouveau module). Pas d'impact sur le TCK Jakarta
REST 4.0 (2535/2535 PASS contrat) — vérifié par la compilation du reactor cassini complet.
