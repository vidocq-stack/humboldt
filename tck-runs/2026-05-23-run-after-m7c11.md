## Item livré en M7c.11

Spec MP Telemetry 2.1 §3.1 :
> By default, the OpenTelemetry SDK is disabled. To enable it, set `otel.sdk.disabled=false`.

OTel SDK Java natif a le défaut inverse (`disabled=false`), mais pour conformité
MP Telemetry, humboldt suit le défaut MP.

**Patch `HumboldtAutoConfigure.configure(env, extras)`** :
- Lit `OTEL_SDK_DISABLED` avec défaut `true`
- Si disabled : construit `SdkTracerProvider`/`SdkMeterProvider`/`SdkLoggerProvider`
  **sans aucun processor** → l'API OTel reste utilisable (`Span.current()`,
  `Tracer.spanBuilder()`) mais aucun signal n'est jamais exporté
- Retourne `AutoConfiguredHumboldt` avec InMemory exporters = null
- Sinon : comportement actuel (otel.sdk.disabled=false → pipeline complet)

**Mise à jour `HumboldtAutoConfigureTest`** :
- Tous les tests existants set explicitement `OTEL_SDK_DISABLED=false` (sinon le
  changement de défaut casse leurs assertions sur les InMemory exporters)
- 2 nouveaux tests :
  - `sdk_disabled_by_default_per_mp_telemetry_spec` : sans config explicite,
    inMemorySpanExporter() == null + 0 SpanProcessor
  - `sdk_disabled_true_explicit_disables_all_pipelines` : OTEL_SDK_DISABLED=true
    explicite + tous les exporters in-memory → tous null
