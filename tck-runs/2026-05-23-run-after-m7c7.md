- `CassiniClientFeatureContext` (FeatureContext → Client adapter)

  invokes `feature.configure(featureCtx)` on each one (skip if already registered by user)
- module-info: `uses jakarta.ws.rs.core.Feature`

### Humboldt-rest (M7c.7)
- `HumboldtClientRequestFilter` (`@Priority(HEADER_DECORATOR)`): starts `kind=CLIENT` span,
  OTel SemConv 1.27+ attrs (`http.request.method`, sanitized `url.full`,
  `server.address`, `server.port` if non-default), injects W3C `traceparent` into outgoing
  headers via `putSingle`, stores span+scope via `setProperty`
- `HumboldtClientResponseFilter` (`@Priority(HEADER_DECORATOR)`): sets
  `http.response.status_code`, status `ERROR` if ≥ 400 (difference vs SERVER, which is
  ERROR only ≥ 500, compliant with OTel HTTP §4.3), closes scope + ends span
- `HumboldtClientTracingFeature implements Feature`: registers the 2 filters;
  automatically discovered by `CassiniClientBuilder` via `META-INF/services/jakarta.ws.rs.core.Feature`
- `module-info.java`: `provides jakarta.ws.rs.core.Feature with HumboldtClientTracingFeature`

## Why the net PASS is unchanged

The `testIntegrationWithJaxRsClient*` tests (which exercise JAX-RS Client + assert that a
CLIENT span is created) benefit from the infrastructure. But they still FAIL because:

1. **Server-side BaggageResource returns HTTP 500** on the first call. This is an
   orthogonal blocker: BaggageResource has `@Inject Baggage baggage;` (CDI) — we need
   to add a `Baggage` Producer in `HumboldtTelemetryProducers`. Without it, any test
   hitting this endpoint receives 500 before even evaluating spans.

2. **CustomizerSpiTest / ResourceSpiTest / SamplerSpiTest**: Cluster D autoconfigure SPI
   (Customizer/Resource/Sampler) — not related to M7c.7.

3. **`testIntegrationWithMpRestClient*`**: needs cyrano instrumentation (CLIENT filters
   on the MP Rest Client side) — that is M7c.12.

4. **W3*PropagationTest**: optional non-W3C propagator tests (B3, Jaeger) —
   Cluster D.

5. **Metrics tests (Double/Long Counter/Histogram/Observable)**: full M4b SDK metric,
   independent of M7c.7.

## Validation that the infrastructure works

`CassiniClientBuilder.build()` does scan the ServiceLoader (verified through Java Modules `uses`
and `META-INF/services` packaged in the humboldt-rest jar). The filters are loaded —
but their effect is observable only in tests that both (a) reach the runtime
without a prior 500 and (b) assert on specific CLIENT spans.
