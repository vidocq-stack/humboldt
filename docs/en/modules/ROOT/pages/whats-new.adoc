= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* xref:reference.adoc#checkpoint-restore[Checkpoint and restore (CRaC)] — `AutoConfiguredHumboldt.release()` exports what is queued and closes the OTLP exporters' connections to the collector, which a CRaC checkpoint refuses; `reopen()` takes them back after the restore.
* xref:reference.adoc#context-debug[Context diagnostics] — `-Dhumboldt.context.debug=true` adds the attach and detach stacks to the `Context attach/detach order mismatch` warning. The cause found with it is fixed: a REST client call that got no response (timeout, connection error, shutdown) left its scope attached on the calling thread, so the next scope closed there reported a mismatch; the CLIENT filter no longer holds a scope across the call.
* xref:internals.adoc#generated-code[Generated code and reflective fallback] — what is generated for Humboldt at build (by Vauban's and Cassini's processors, Humboldt having no generator of its own), what uses it at run time, and what is still read once by reflection and cached: the `@WithSpan` span plan and the `http.route` template.
* *OpenTelemetry 1.67.0* — the repackaged OpenTelemetry API and context move from 1.66.0 to 1.67.0, which fixes GHSA-ccrj-gw8r-854m: a crafted `tracestate` request header made the W3C trace-context propagator parse in quadratic time (an unauthenticated CPU denial of service). No API change for applications. See xref:reference.adoc#compatibility[Compatibility].
* xref:reference.adoc#exporter-defaults[Exporters default to `otlp`] — with an OTLP endpoint set, traces, metrics and logs are exported without naming `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER` and `OTEL_LOGS_EXPORTER`, as the OpenTelemetry SDK does.
* On Cassini, `http.route` is the resource's template (`/books/{id}`) again, not the concrete path: `humboldt-rest` ships the Cassini adapter of its request filter, so the server span name and the `http.server.request.duration` series no longer multiply per id.
* *No test library in an application* — spans are mapped to Humboldt's own `SpanData` instead of the SDK's `TestSpanData`, so `opentelemetry-sdk-testing` is no longer a dependency of a packaged application.
* *SDK and CDI fixes* — the batch worker wakes when a full batch is queued; a flush or a shutdown completes only once the data is exported, and a metric reader exports its final collection once on shutdown; asynchronous counters report their observed value; a link added to a started span is recorded; `CompletableResultCode` fails on a join timeout or interrupt; the current `Span` and `Baggage` are injected through written delegates; `@SpanAttribute` values keep their type, and each method is planned once.
