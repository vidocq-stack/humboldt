## Pourquoi le PASS net est inchangé

Les tests `testIntegrationWithJaxRsClient*` (qui exercent JAX-RS Client + assertent qu'un
span CLIENT est posé) bénéficient de l'infra. Mais ils restent FAIL parce que :

1. **BaggageResource côté serveur retourne HTTP 500** dès le premier appel. C'est un
   bloqueur orthogonal : le BaggageResource a `@Inject Baggage baggage;` (CDI) — il faut
   ajouter un Producer `Baggage` dans `HumboldtTelemetryProducers`. Sans cela, tout test
   qui hit cet endpoint reçoit 500 avant même d'évaluer les spans.

2. **CustomizerSpiTest / ResourceSpiTest / SamplerSpiTest** : cluster D autoconfigure SPI
   (Customizer/Resource/Sampler) — pas lié à M7c.7.

3. **testIntegrationWithMpRestClient*** : besoin d'instrumentation cyrano (filtres CLIENT
   côté MP Rest Client) — c'est M7c.12.

4. **W3*PropagationTest** : tests propagateurs non-W3C (B3, Jaeger) marqués optional —
   cluster D.

5. **Metrics tests (Double/Long Counter/Histogram/Observable)** : M4b SDK metric complet,
   indépendant de M7c.7.
